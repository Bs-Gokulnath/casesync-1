## Summary of real bugs found and fixed while building this
Caught by actually running the stack and testing as non-superuser roles,
not just by code review — listed here because they're the clearest evidence
the verification was real:
1. Next 16 bakes `next.config.ts`'s `rewrites()` into the build manifest at
   `next build` time; setting the destination only via `docker-compose.yml`'s
   `environment:` block was silently ignored by the already-built image
   (Phase 2).
2. The Overlaps page requested `page_size=200` from `/institutions`, which
   the backend caps at 100, causing a 422 → unhandled 500 (Phase 3b).
3. `_region_counts` in the analytics service joined `Institution` but
   selected columns from a `Complaint`-only subquery, so `Institution.region_id`
   didn't exist on it (Phase 6).
4. Four dashboard pages/actions had no server-side permission guard, so a
   role lacking that specific permission got an unhandled exception and a
   500 page instead of a clean redirect, found only by testing as `auditor`
   and `bureau_officer` instead of just `system_admin` (Phase 6).

Each phase ends with: migrations applied cleanly on a fresh DB, relevant
pytest/vitest suites run, and a short note here of what actually passed vs.
what could not be verified in this environment (e.g. no local Docker daemon
available at execution time).

## Known environment constraints (confirmed Phase 0)

  `venv` + `requirements.txt`.
- No pnpm/yarn → frontend uses npm.
- No local `psql`/Postgres → Postgres only via Docker Compose; backend tests
  that need a DB require `docker compose up -d postgres` first, documented in
  README.

  full stack can be brought up locally.
